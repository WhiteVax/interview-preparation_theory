### Почему важно понимать и уметь применять алгоритмы на собеседованиях?
1. Алгоритмы — это фильтр на уровень мышления

Собеседование проверяет не только знание языка или фреймворков.
Алгоритмы и структуры данных показывают, как думают:

+ умеют ли разбивать сложную задачу на части
+ понимают ли компромиссы (время vs память, простота vs эффективность)
+ способны ли найти оптимальное, а не просто «рабочее» решение
+ умеют ли оценивать сложность алгоритмов (Big O)

Компании ищут не просто «кодеров», а инженеров, способных решать новые и нетривиальные задачи.

2. Практическая польза в работе

Алгоритмы — это не только про собеседования. Они постоянно применяются в реальной разработке:

+ оптимизация производительности (медленные API, БД, UI)
+ работа с большими объемами данных
+ кэширование и очереди
+ поиск, фильтрация, дедупликация данных
+ работа со строками, деревьями, графами
+ элементы динамического программирования в бизнес-логике

Разработчик с алгоритмическим мышлением пишет код, который:

+ быстрее
+ масштабируемее
+ надежнее

3. Собеседования по-прежнему строятся вокруг алгоритмов

Типичный процесс в сильных компаниях:

+ Screening / Online assessment — задачи уровня Easy/Medium
+ Technical interview (1–2 этапа) — Medium/Hard + обсуждение решения
+ System Design (для Middle+/Senior) — структуры данных тоже важны
+ Behavioral interview

Если кандидат не решает уверенно задачи уровня Medium за 30–45 минут — его часто отсеивают, даже при хорошем опыте.

4. Алгоритмы — это сигнал для компании

Навыки решения алгоритмических задач показывают:

+ способность быстро учиться
+ дисциплину (регулярная практика)
+ аналитическое мышление
+ умение работать под давлением (таймер, интервьюер)

5. Высокая конкуренция

На одну позицию может быть 100–500+ кандидатов.
Алгоритмы — это удобный и объективный способ фильтрации.

Особенно это важно для:

+ Junior / Middle позиций
+ топовых компаний
+ релокации за границу

Когда алгоритмы менее критичны

Есть ситуации, где алгоритмы играют меньшую роль:

+ небольшие стартапы без строгого процесса
+ аутсорс / аутстафф компании
+ узкоспециализированные роли (верстка, DevOps, QA automation)
+ Senior/Lead — больше упор на System Design и опы

Алгоритмы и структуры данных — это универсальный язык общения между разработчиком и компанией.

Это не про заучивание сотен задач, а про развитие мышления, которое делает тебя сильнее как инженера.
### Какова структура типичного вопроса на собеседовании, связанного с алгоритмами?
Структура типичного алгоритмического вопроса на собеседовании

Алгоритмическое собеседование (LeetCode-style) проходит в реальном времени (45–60 минут) и имеет стандартную структуру.

1. Постановка задачи (1–2 минуты)

Интервьюер описывает условие задачи.

Пример:
найти два индекса в массиве, сумма которых равна target (Two Sum).

2. Уточнение требований (3–5 минут)

Кандидат задаёт вопросы, чтобы прояснить задачу:

+ ограничения на размер входных данных
+ допустимые значения (отрицательные, дубликаты и т.д.)
+ формат результата (индексы / значения / boolean)
+ ограничения по времени и памяти
+ можно ли изменять входные данные

Цель: избежать неверных предположений и показать инженерное мышление.

3. Разбор примеров (3–5 минут)
   + анализ примера из условия
   + добавление собственных примеров
   + проверка edge cases:
     + пустой массив
     + один элемент
     + дубликаты
     + отсутствие решения
     + крайние значения
4. Выбор подхода (5–10 минут)

Кандидат предлагает варианты:

+ наивное решение (brute force)
+ оптимизированное решение

Обсуждает:

+ временную сложность (Big O)
+ потребление памяти
+ компромиссы (trade-offs)

Выбирает лучший подход.

5. Реализация (10–20 минут)

Написание кода:

+ понятные имена переменных
+ учёт edge cases
+ логичная структура

Важно: лучше сначала рабочее решение, потом улучшения.

6. Тестирование (3–5 минут)
   + прогон по примерам
   + проверка граничных случаев
   + исправление ошибок
7. Оптимизация и follow-up

Дополнительные вопросы:

+ можно ли улучшить решение
+ как изменится решение при других условиях
+ обобщение задачи

Что оценивается
+ умение думать и объяснять
+ структурированный подход
+ знание алгоритмов и структур данных
+ внимание к edge cases
+ скорость решения

Краткий шаблон (must-have)

Clarify → Examples → Approach → Code → Test

### Два указателя

### Что такое метод "двух указателей" и когда он используется?
Метод двух указателей — это алгоритмический паттерн, при котором вместо одного индекса используются два указателя (обычно left и right), которые двигаются по структуре данных по определённым правилам.

Основная цель — уменьшить сложность алгоритма, чаще всего с O(n²) до O(n).

Вместо перебора всех пар элементов (двойной цикл):
+ ставим два указателя
+ двигаем их по условию задачи
+ избегаем повторных проверок

Как могут двигаться указатели?

Навстречу друг другу (Opposite Ends)


	left = 0, right = n - 1

используются в отсортированных массивах

В одном направлении (Fast & Slow)
+ один указатель идёт быстрее другого
+ часто называют "черепаха и заяц"

Независимое движение

+ указатели могут стартовать в разных местах и двигаться по своим правилам

Основные паттерны

1. Указатели с концов (Inward / Opposite Ends)
```java
left, right = 0, len(arr) - 1

while left < right:
    if условие:
        left += 1
    else:
        right -= 1
```
+ отсортированные массивы
+ поиск пары (sum, diff)
+ задачи на симметрию

2. Fast & Slow (быстрый и медленный)


	slow, fast = 0, 0

```java
while fast < len(arr):
    # логика
    fast += 1
```
+ удаление элементов in-place
+ поиск середины
+ обнаружение цикла (linked list)

3. Sliding Window (скользящее окно)

Частный случай двух указателей.
```java
left = 0

for right in range(len(arr)):
    // расширяем окно
    
    while условие нарушено:
        left += 1  # сужаем окно
```
+ подмассивы / подстроки
+ сумма, длина, максимум, количество

Когда использовать

Массив отсортирован или можно отсортировать

Нужно найти:
+ пару / триплет элементов
+ сумму = target

Работа с:
+ палиндромами
+ подстроками / подмассивами

Нужно:
+ удалить дубликаты
+ сделать in-place преобразование

Связанные списки:
+ середина
+ цикл

Есть намёк на оптимизацию:
+ из O(n²) → в O(n)

Классические задачи

1. Two Sum II (отсортированный массив)

def twoSum(numbers, target):
```java
    left, right = 0, len(numbers) - 1
    
    while left < right:
        s = numbers[left] + numbers[right]
        
        if s == target:
            return [left + 1, right + 1]
        elif s < target:
            left += 1
        else:
            right -= 1
            
    return []
```
Сложность: O(n)

2. Проверка палиндрома
+ указатели идут с концов
+ пропускают невалидные символы
+ сравнивают символы

3. Remove Duplicates (in-place)
+ slow — позиция записи
+ fast — проход по массиву

4. Container With Most Water
+ указатели с концов
+ двигаем тот, у кого высота меньше

5. Sum
+ сортировка (O(n log n))
+ фиксируем один элемент
+ для остальных — two pointers

6. Linked List задачи
   Середина списка
+ fast идёт в 2 раза быстрее

Поиск цикла
+ алгоритм Флойда

Отличие от Sliding Window

| Two Pointers                            | Sliding Window          |
| --------------------------------------- | ----------------------- |
| Сравнение двух позиций                  | Работа с диапазоном     |
| Указатели могут двигаться в обе стороны | Движение только вправо  |
| Не обязательно учитывать всё между      | Всегда учитывается окно |

Sliding Window — это подвид two pointers.

O(n) (или O(n log n) с сортировкой)

Память:

O(1) (in-place)

Частые ошибки
+ Неправильное движение указателей
+ Забыли про отсортированность
+ Не обработаны edge cases:
    + пустой массив
    + один элемент
    + все элементы одинаковые
+ Бесконечный цикл (left и right не меняются)

Советы для собеседования
+ Начни с brute-force (O(n²))
+ Затем предложи оптимизацию → two pointers

Проговаривай:
+ почему двигаешь конкретный указатель

Уточняй:
+ отсортирован ли массив?
+ можно ли его сортировать?
### Приведите пример задачи, решаемой с помощью двух указателей.
Пример задачи на Two Pointers

Container With Most Water (LeetCode 11)

+ Дан массив неотрицательных чисел height, где каждый элемент — высота вертикальной линии.
+ Нужно выбрать две линии, которые вместе с осью X образуют контейнер с максимальной площадью воды.

Формула площади:
+ area = min(height[i], height[j]) * (j - i)
+ высота = меньшая из двух линий
+ ширина = расстояние между ними

Примеры
+ Вход:  [1,8,6,2,5,4,8,3,7]
+ Выход: 49
+ Вход:  [1,1]
+ Выход: 1
+ Вход:  [4,3,2,1,4]
+ Выход: 16

Почему здесь подходит Two Pointers?

Brute-force:
+ перебрать все пары → O(n²)
+ слишком медленно при n до 10⁵

Оптимально:
+ используем два указателя
+ сложность → O(n)

Идея алгоритма

Ставим указатели:
+ left = 0
+ right = n - 1

Пока left < right:
+ считаем площадь
+ обновляем максимум
+ двигаем указатель с меньшей высотой

Почему двигаем меньший указатель?
+ Площадь ограничена минимальной высотой.

Если сдвинуть более высокий:
+ ширина уменьшится

высота не увеличится
→ площадь точно не станет больше

Если сдвинуть меньший:

есть шанс найти более высокую линию
→ потенциально увеличить площадь

```java
public class ContainerWithMostWater {

    public static int maxArea(int[] height) {
        int left = 0;
        int right = height.length - 1;

        int maxArea = 0;

        while (left < right) {
            int width = right - left;
            int currentHeight = Math.min(height[left], height[right]);
            int area = currentHeight * width;

            maxArea = Math.max(maxArea, area);

            // Двигаем указатель с меньшей высотой
            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }

        return maxArea;
    }

    public static void main(String[] args) {
        int[] arr = {1,8,6,2,5,4,8,3,7};
        System.out.println(maxArea(arr)); // 49
    }
}
```
Для массива:
+ [1,8,6,2,5,4,8,3,7]
+ left=0, right=8 → площадь = 1 * 8 = 8

двигаем left (меньше)
+ left=1, right=8 → площадь = 7 * 7 = 49
+ продолжаем сужать окно

Сложность
+ Время: O(n)
+ Память: O(1)

Edge cases
+ Минимальный размер: n = 2
+ Все элементы одинаковые
+ Все элементы = 0
+ Массив строго убывающий/возрастающий

Частые ошибки

+ Двигать оба указателя одновременно
+ Двигать больший вместо меньшего
+ Забыть обновить максимум
+ Неправильно считать ширину (right - left)

Follow-up вопросы
+ Можно ли быстрее? → нет, O(n) оптимально
+ Что если нужно вернуть индексы? → сохраняем их при обновлении max
+ Что если массив не помещается в память? → стриминг/батчи (редкий кейс)
### Каковы преимущества и недостатки метода двух указателей?
Преимущества и недостатки метода двух указателей

| Преимущество                                | Пояснение                                                | Почему важно                              |
| ------------------------------------------- | -------------------------------------------------------- | ----------------------------------------- |
| **Высокая скорость**                        | Обычно `O(n)` или `O(n log n)` (если нужна сортировка)   | Значительно быстрее brute-force (`O(n²)`) |
| **Экономия памяти**                         | Дополнительная память — `O(1)`                           | Критично при больших данных               |
| **Простота после освоения**                 | Код компактный и читаемый                                | Легко писать и объяснять на интервью      |
| **Эффективность на отсортированных данных** | Отлично работает с упорядоченными массивами              | Часто можно отсортировать вход            |
| **In-place обработка**                      | Можно изменять массив без доп. структур                  | Важно при ограничениях по памяти          |
| **Хорошо комбинируется**                    | Используется внутри других алгоритмов (например, в 3Sum) | Повышает универсальность                  |
| **Снижает вложенность**                     | Убирает двойные циклы                                    | Делает код быстрее и чище                 |

Недостатки и ограничения

| Недостаток                    | Пояснение                                                | Когда это проблема                    |
| ----------------------------- | -------------------------------------------------------- | ------------------------------------- |
| **Требует упорядоченности**   | Часто нужен отсортированный массив                       | Если сортировка запрещена или дорогая |
| **Не универсален**            | Подходит не ко всем задачам                              | Нет монотонности → метод не работает  |
| **Сложность понимания**       | Не всегда очевидно, какой указатель двигать              | Нужно уметь объяснить на интервью     |
| **Ошибки в логике движения**  | Легко сделать неверный шаг                               | Приводит к неправильному ответу       |
| **Сложность отладки**         | Поведение указателей может быть неочевидным              | Особенно для новичков                 |
| **Ограниченность применения** | Плохо работает с несмежными/неструктурированными данными | Лучше использовать другие подходы     |
| **Риск пропустить решение**   | При неправильной стратегии                               | Требует хорошего понимания задачи     |

Когда лучше НЕ использовать

Метод двух указателей не подходит, если:
+ Нужно найти все комбинации (подмножества, а не пары)
+ Нельзя менять порядок элементов (и нельзя сортировать)

Работа с:
+ графами
+ деревьями
  → лучше DFS/BFS
+ Есть перекрывающиеся подзадачи
  → лучше динамическое программирование
+ Данные приходят потоком (streaming)
  → иногда лучше sliding window или другие техники


Сравнение

| Подход             | Время      | Память | Когда использовать              |
| ------------------ | ---------- | ------ | ------------------------------- |
| **Brute Force**    | `O(n²)`    | `O(1)` | Когда важно быстро написать     |
| **Two Pointers**   | `O(n)`     | `O(1)` | Пары, отсортированные данные    |
| **HashMap / Set**  | `O(n)`     | `O(n)` | Когда нельзя сортировать        |
| **Sliding Window** | `O(n)`     | `O(1)` | Подмассивы/подстроки            |
| **Binary Search**  | `O(log n)` | `O(1)` | Поиск в отсортированном массиве |

Если в задаче есть:
+ отсортированный массив
+ поиск пары / триплета

условия типа:
+ sum = target
+ max/min
+ симметрия

Сразу думай про two pointers

Если массив не отсортирован:
+ сначала уточни, можно ли его отсортировать


### Hash структуры

### Что такое хеш-таблица и как она работает?
**Хеш-таблица** — это структура данных, которая хранит пары **ключ → значение** и обеспечивает быстрый доступ к данным за счёт преобразования ключа в индекс массива.

В Java она реализована классом:

* `HashMap<K, V>`
* `HashSet<E>` (использует HashMap внутри)

| Метод                       | Описание                                 |
| --------------------------- | ---------------------------------------- |
| Цепочки (LinkedList / Tree) | В одной ячейке хранится список элементов |
| Открытая адресация          | Поиск следующей свободной ячейки         |

* до Java 8 → список (`LinkedList`)
* после Java 8 → список + дерево (`TreeNode` при большом количестве элементов)

```text
[0] → null
[1] → Node → Node → Node
[2] → TreeNode (если много коллизий)
...
```

### Объясните принцип работы метода хеширования.
**Структура HashMap**

В основе лежит массив:

```java
Node<K,V>[] table;
```

Каждая ячейка массива (bucket) может хранить:

* `null`
* один `Node`
* связанный список (`Node → Node → ...`)
* красно-чёрное дерево (`TreeNode`)

**Что происходит при `put(key, value)`**

```java
HashMap<String, Integer> map = new HashMap<>();
map.put("apple", 10);
```
**Шаг 1: Получение hashCode()**

```java
int hash = key.hashCode();
```

Для строки `"apple"`:

```text
hash = 93029210 (пример)
```
**Шаг 2: Улучшение хеша (spread)**

Java делает дополнительное перемешивание битов:

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

* чтобы **равномернее распределить значения**
* уменьшить коллизии

**Шаг 3: Вычисление индекса**

```java
int index = (n - 1) & hash;
```
* `n` — размер массива (всегда степень двойки: 16, 32, 64...)

Пример:

```text
n = 16
index = hash & 15
```
* `&` быстрее (битовая операция)

**Шаг 4: Проверка bucket**

```java
Node<K,V> first = table[index];
```
Сценарии:

| Ситуация        | Что происходит      |
| --------------- | ------------------- |
| Пусто           | Просто вставляем    |
| Есть 1 элемент  | Сравниваем ключи    |
| Есть цепочка    | Ищем нужный ключ    |
| Много элементов | Может стать деревом |

**Шаг 5: Сравнение ключей**

```java
if (node.hash == hash && (node.key.equals(key)))
```

* сначала сравнивается hash
* потом equals()

**Шаг 6: Обработка коллизий**

Коллизия = одинаковый индекс

До Java 8:

```text
[index] → Node → Node → Node
```

После Java 8:

Если элементов > 8:

```text
[index] → TreeNode (красно-чёрное дерево)
```
**Шаг 7: Добавление элемента**

Если ключ не найден:

```java
new Node(hash, key, value, next);
```
**Что происходит при `get(key)`**

```java
map.get("apple");
```
Алгоритм:

1. Вычисляется hash
2. Находится index
3. Берётся bucket
4. Проверяется:

    * первый элемент
    * затем цепочка / дерево

**Поиск:**

* список → O(n)
* дерево → O(log n)

**Коллизии — ключевая проблема**

Пример:

```java
map.put("Aa", 1);
map.put("BB", 2);
```

У них одинаковый hashCode → коллизия

**Что делает HashMap:**

* кладёт их в один bucket
* связывает через список или дерево

**Resize (расширение таблицы)**

Когда происходит:

```java
threshold = capacity * loadFactor;
```

По умолчанию:

```text
capacity = 16
loadFactor = 0.75
threshold = 12
```
При добавлении 13-го элемента:

* массив увеличивается до 32
* все элементы перераспределяются

Важный момент: перерасчёт индекса

При resize НЕ пересчитывается hashCode
меняется только index:

```text
старый index → либо тот же, либо + oldCapacity
```
Это оптимизация Java 8+

**Почему всё работает быстро**

| Причина           | Объяснение                |
| ----------------- | ------------------------- |
| Прямой доступ     | index вычисляется сразу   |
| Хороший hash      | равномерное распределение |
| Низкий loadFactor | мало коллизий             |
| Деревья           | защита от O(n)            |


**Критически важные требования к ключам**

`equals()` и `hashCode()`

ДОЛЖНЫ быть согласованы:

```java
if (a.equals(b)) → a.hashCode() == b.hashCode()
```
Пример ошибки

```java
class User {
    String name;
}
```

Без equals/hashCode:
👉 HashMap будет работать неправильно

**Полный жизненный цикл вставки**

```text
key → hashCode()
     → hash (spread)
     → index
     → bucket
        → пусто → вставка
        → есть элементы
            → поиск ключа
                → найден → update
                → нет → добавление
     → проверка threshold
        → resize (если нужно)
```

Итоговая таблица

| Этап       | Что происходит     |
| ---------- | ------------------ |
| hashCode() | получаем число     |
| hash()     | перемешивание      |
| index      | вычисление позиции |
| bucket     | выбор ячейки       |
| equals()   | проверка ключа     |
| collision  | обработка          |
| resize     | расширение         |


**Коротко**

HashMap работает так:

> "Берём ключ → превращаем в число → вычисляем индекс → кладём в массив → при конфликте используем список или дерево"

Хеширование — это:

* не просто `hashCode()`
* а **вся цепочка: hash → index → bucket → структура внутри**

Именно это даёт:
**O(1) доступ в среднем**

### Сортировки

### Назовите основные алгоритмы сортировки и их временные сложности.

| Алгоритм       | Средняя сложность | Худший случай | Память   | Стабильность | Кратко                               |
| -------------- | ----------------- | ------------- | -------- | ------------ | ------------------------------------ |
| Bubble Sort    | O(n²)             | O(n²)         | O(1)     | да            | Простая, но медленная                |
| Selection Sort | O(n²)             | O(n²)         | O(1)     | нет            | Всегда одинаково медленная           |
| Insertion Sort | O(n²)             | O(n²)         | O(1)     | да            | Отлично для почти отсортированных    |
| Merge Sort     | O(n log n)        | O(n log n)    | O(n)     | да            | Стабильная, гарантированная скорость |
| Quick Sort     | O(n log n)        | O(n²)         | O(log n) | нет            | Очень быстрая на практике            |
| Heap Sort      | O(n log n)        | O(n log n)    | O(1)     | нет            | Без доп. памяти                      |
| TimSort (Java) | O(n log n)        | O(n log n)    | O(n)     | да           | Гибрид, используется в Java          |

### В чем отличие быстрой сортировки от сортировки слиянием?

**Quick Sort** (Быстрая сортировка)

*Идея:*

* выбрать pivot (опорный элемент)
* разбить массив на:

    * меньше pivot
    * больше pivot
* рекурсивно сортировать

*Плюсы:*

* Очень быстрая на практике
* Хорошая кэш-локальность
* O(log n) память

*Минусы:*

* Худший случай O(n²)
* Не стабильная
* Зависит от выбора pivot


**Merge Sort (Сортировка слиянием)**

*Идея:*

* делим массив пополам
* сортируем части
* сливаем

*Плюсы:*

* Всегда O(n log n)
* Стабильная
* Хороша для больших данных и потоков

*Минусы:*

* Требует O(n) памяти
* Медленнее QuickSort на практике (из-за копирования)

*Ключевые отличия*

| Критерий              | Quick Sort | Merge Sort   |
| --------------------- | ---------- | ------------ |
| Средняя сложность     | O(n log n) | O(n log n)   |
| Худший случай         | ❌ O(n²)    | ✅ O(n log n) |
| Память                | O(log n)   | O(n)         |
| Стабильность          | ❌          | ✅            |
| Локальность памяти    | ✅          | ❌            |
| Практическая скорость | 🔥 быстрее | медленнее    |
### Какой алгоритм сортировки лучше использовать для почти отсортированных данных?
Лучший выбор: **Insertion Sort**

*Почему:*

* Работает за **O(n)** если массив почти отсортирован
* Минимум операций
* Простая реализация

*Альтернатива (Java)*

TimSort (используется в `Arrays.sort()` для объектов)

Почему он лучший:

* определяет "почти отсортированные" участки (runs)
* комбинирует:

    * Insertion Sort
    * Merge Sort

Поэтому:

```java
Arrays.sort(array);
```

— уже оптимален для почти отсортированных данных


## Очереди и стеки

### Что такое очередь и стек? В чем их отличие?
**Стек (Stack)**

**Стек** — это структура данных, работающая по принципу:

> **LIFO (Last In, First Out)** — последний пришёл, первый вышел

Пример:

```text
Добавили: A → B → C
Извлекаем: C → B → A
```

Основные операции:

| Операция  | Описание           | Сложность |
| --------- | ------------------ | --------- |
| push()    | добавить элемент   | O(1)      |
| pop()     | удалить верхний    | O(1)      |
| peek()    | посмотреть верхний | O(1)      |
| isEmpty() | пуст ли стек       | O(1)      |

**Очередь (Queue)**

**Очередь** — структура данных с принципом:

> **FIFO (First In, First Out)** — первый пришёл, первый вышел

Пример:

```text
Добавили: A → B → C
Извлекаем: A → B → C
```
Основные операции:

| Операция          | Описание          | Сложность |
| ----------------- | ----------------- | --------- |
| offer() / add()   | добавить в конец  | O(1)      |
| poll() / remove() | удалить из начала | O(1)      |
| peek()            | посмотреть первый | O(1)      |
| isEmpty()         | пусто ли          | O(1)      |

Отличие стека от очереди

| Критерий      | Стек              | Очередь        |
| ------------- | ----------------- | -------------- |
| Принцип       | LIFO              | FIFO           |
| Добавление    | в конец (верх)    | в конец        |
| Удаление      | с конца           | с начала       |
| Доступ        | только к вершине  | к началу       |
| Использование | рекурсия, парсинг | потоки, задачи |

### Объясните принцип работы очереди с приоритетом.
**Что это такое**

**Очередь с приоритетом** — это очередь, где элементы извлекаются не по порядку добавления, а по **приоритету**.

```java
PriorityQueue<Integer> pq = new PriorityQueue<>();
```

**Принцип работы**

Основана на **куче (heap)**:

* по умолчанию → **min-heap**
* на вершине → минимальный элемент

Пример:

```java
pq.add(5);
pq.add(1);
pq.add(3);
```

```text
Извлечение:
1 → 3 → 5
```

**Внутреннее устройство (heap)**

```text
        1
      /   \
     5     3
```

> Родитель ≤ дети

**Операции и сложность**

| Операция | Сложность |
| -------- | --------- |
| add()    | O(log n)  |
| poll()   | O(log n)  |
| peek()   | O(1)      |

**Кастомный приоритет**

```java
PriorityQueue<Integer> pq = new PriorityQueue<>((a, b) -> b - a);
```
теперь max-heap

### Приведите примеры использования очередей и стеков в реальных задачах.

**Стек (Stack)**

| Задача            | Почему стек              |
| ----------------- | ------------------------ |
| Рекурсия          | стек вызовов             |
| Проверка скобок   | LIFO логика              |
| Undo/Redo         | последний шаг отменяется |
| DFS (графы)       | углубление               |
| Парсинг выражений | порядок операций         |

**Очередь (Queue)**

| Задача             | Почему очередь            |
| ------------------ | ------------------------- |
| BFS (графы)        | обход по уровням          |
| Очередь задач      | порядок выполнения        |
| Обработка запросов | first come first served   |
| Буферы (IO)        | последовательность данных |

**Priority Queue**

| Задача            | Почему                   |
| ----------------- | ------------------------ |
| Dijkstra          | нужен минимальный вес    |
| Планировщик задач | приоритет выполнения     |
| Huffman coding    | минимальные частоты      |
| Top-K задачи      | быстрый доступ к min/max |


Итог

| Структура      | Принцип       | Когда использовать  |
| -------------- | ------------- | ------------------- |
| Стек           | LIFO          | рекурсия, откаты    |

### Скользящее окно

### Что такое метод скользящего окна и для каких задач он подходит?
**Метод скользящего окна** — это алгоритмический приём, при котором мы рассматриваем **подмассив или подстроку фиксированного или переменного размера**, двигая границы окна по данным вместо полного перебора всех вариантов.

Идея:

> не пересчитывать заново, а **обновлять результат при сдвиге окна**
### Приведите пример задачи, решаемой с помощью метода скользящего окна.
Метод применяется, когда:

* нужно работать с **непрерывным участком** (subarray / substring)
* требуется:

    * сумма
    * максимум/минимум
    * количество уникальных элементов
    * проверка условий внутри окна

**Типы окон**

1. Фиксированное окно

Размер окна заранее задан

```text
[ i ... i+k-1 ]
```

2. Динамическое окно

Размер изменяется в процессе (два указателя)

```text
[left ... right]
```

**Как работает (общая схема)**

```java
int left = 0;

for (int right = 0; right < n; right++) {
    // расширяем окно

    while (условие нарушено) {
        // сужаем окно
        left++;
    }
    // обновляем ответ
}
```
**Пример задачи**

Задача:

**Найти максимальную сумму подмассива длины k**

Наивный подход:

* перебор всех подмассивов → O(n * k)

**Sliding Window:**

```java
int maxSum = 0;
int windowSum = 0;

// первое окно
for (int i = 0; i < k; i++) {
    windowSum += arr[i];
}

maxSum = windowSum;

// двигаем окно
for (int i = k; i < arr.length; i++) {
    windowSum += arr[i];      // добавили новый элемент
    windowSum -= arr[i - k];  // убрали старый

    maxSum = Math.max(maxSum, windowSum);
}
```

**Иллюстрация**

```text
[2, 1, 5, 1, 3, 2], k = 3

Окна:
[2,1,5] → 8
[1,5,1] → 7
[5,1,3] → 9 ← max
[1,3,2] → 6
```

**Пример с динамическим окном**

Задача:

**Найти самую длинную подстроку без повторяющихся символов**

```java
Set<Character> set = new HashSet<>();
int left = 0, maxLen = 0;

for (int right = 0; right < s.length(); right++) {
    while (set.contains(s.charAt(right))) {
        set.remove(s.charAt(left));
        left++;
    }

    set.add(s.charAt(right));
    maxLen = Math.max(maxLen, right - left + 1);
}
```
### Какова временная сложность алгоритмов, использующих метод скользящего окна?

Главное свойство:

| Тип окна      | Сложность |
| ------------- | --------- |
| Фиксированное | O(n)      |
| Динамическое  | O(n)      |

Почему O(n), а не O(n²):

* каждый элемент:

    * добавляется в окно **1 раз**
    * удаляется из окна **1 раз**

Итого:

```text
left → n шагов
right → n шагов
=> O(n)
```
Сравнение с brute force

| Подход         | Сложность     |
| -------------- | ------------- |
| Полный перебор | O(n²) / O(n³) |
| Sliding Window | O(n)          |

ускорение в разы

Где часто применяется

| Задача                         | Тип окна               |
| ------------------------------ | ---------------------- |
| Максимальная сумма k элементов | фиксированное          |
| Минимальное окно с условием    | динамическое           |
| Подстроки без повторов         | динамическое           |
| Кол-во анаграмм                | фиксированное          |
| Максимум в окне                | deque + sliding window |

Итог

* Sliding Window — это оптимизация перебора подмассивов
* Использует 2 указателя
* Работает за **O(n)**
* Особенно эффективен для **непрерывных данных**

### Жадный алгоритм


### Что такое жадный алгоритм и каковы его основные принципы?
**Жадный алгоритм** — это подход, при котором на каждом шаге выбирается **локально оптимальное решение** в надежде, что оно приведёт к **глобально оптимальному результату**.

Идея:

> "Берём лучшее прямо сейчас, не думая о будущем"

Основные принципы

| Принцип         | Описание                                  |
| --------------- | ----------------------------------------- |
| Локальный выбор | на каждом шаге выбираем наилучший вариант |
| Необратимость   | решение не пересматривается               |
| Простота        | нет перебора всех вариантов               |
| Эффективность   | обычно O(n) или O(n log n)                |

Как работает (общая схема)

```text
1. Отсортировать данные (если нужно)
2. Идти по элементам
3. На каждом шаге выбирать лучший вариант
4. Добавлять его в решение
```

### Приведите пример задачи, решаемой с помощью жадного алгоритма.
Задача: Размен монет

Есть монеты:

```text
[1, 5, 10, 25]
```

Нужно выдать сумму:

```text 
63
```

---

Жадное решение:

```text 
63 → 25 → 25 → 10 → 1 → 1 → 1
```

Всегда берём **самую большую возможную монету**

Пример на Java:

```java 
int[] coins = {25, 10, 5, 1};
int amount = 63;

for (int coin : coins) {
    while (amount >= coin) {
        amount -= coin;
        System.out.println(coin);
    }
}
```
Другие классические задачи

| Задача              | Идея                                         |
| ------------------- | -------------------------------------------- |
| Activity Selection  | выбрать максимум непересекающихся интервалов |
| Huffman Coding      | минимизация длины кодов                      |
| Kruskal / Prim      | минимальное остовное дерево                  |
| Dijkstra            | кратчайший путь (без отрицательных рёбер)    |
| Fractional Knapsack | брать по максимуму ценности                  |

Когда жадный алгоритм НЕ работает

Пример: монеты

```text 
coins = [1, 3, 4]
amount = 6
```

Жадный:

```text 
4 + 1 + 1 = 3 монеты
```

Оптимально:

```text 
3 + 3 = 2 монеты
```

Жадный дал НЕ оптимум

### Какие условия должны выполняться, чтобы жадный алгоритм дал оптимальное решение?
Чтобы greedy дал правильный результат, должны выполняться:

1. Свойство жадного выбора (Greedy Choice Property)

> Локально оптимальный выбор приводит к глобально оптимальному решению

2. Оптимальная подструктура (Optimal Substructure)

> Оптимальное решение задачи состоит из оптимальных решений подзадач

Таблица условий

| Условие              | Суть                        |
| -------------------- | --------------------------- |
| Greedy Choice        | можно выбирать локально     |
| Optimal Substructure | задача делится на подзадачи |

Жадный vs Динамическое программирование

| Критерий             | Greedy    | DP        |
| -------------------- | --------- | --------- |
| Скорость             | быстрее   | медленнее |
| Память               | меньше    | больше    |
| Гарантия оптимума    | не всегда | всегда    |
| Сложность реализации | проще     | сложнее   |

### Деревья

### Что такое дерево в программировании и какие виды деревьев существуют?

**Дерево (Tree)** — это иерархическая структура данных, состоящая из **узлов (nodes)**, связанных отношениями "родитель → потомок".

Свойства:

* есть **корень (root)**
* каждый узел (кроме корня) имеет **одного родителя**
* может иметь **несколько детей**
* нет циклов

**Базовая структура узла**

```java 
class Node {
    int value;
    Node left;
    Node right;
}
```

**Основные виды деревьев**

1. Общее дерево (General Tree)

* любое количество детей

2. Бинарное дерево (Binary Tree)

* не более 2 детей: `left` и `right`

3. Полное бинарное дерево

* все уровни заполнены, кроме последнего

4. Полностью заполненное (Perfect Tree)

* все уровни полностью заполнены

5. Двоичное дерево поиска (BST)

6. Сбалансированные деревья

| Тип            | Особенность                     |
| -------------- | ------------------------------- |
| AVL            | строгий баланс                  |
| Red-Black Tree | баланс с ослабленными правилами |

7. Куча (Heap)

* используется в `PriorityQueue`
* min-heap / max-heap

8. Trie (префиксное дерево)

* для строк и поиска по префиксу

### Объясните, что такое бинарное дерево поиска и его основные операции.

**BST (Binary Search Tree)** — это бинарное дерево, где:

```text
left < root < right
```
Для каждого узла:

* все элементы слева меньше
* все элементы справа больше

Пример

```text 
        8
      /   \
     3     10
    / \      \
   1   6      14
```

**Основные операции BST**

1. Поиск (Search)

```java
Node search(Node root, int key) {
    if (root == null || root.value == key) return root;

    if (key < root.value)
        return search(root.left, key);
    else
        return search(root.right, key);
}
```

2. Вставка (Insert)

```java
Node insert(Node root, int key) {
    if (root == null) return new Node(key);

    if (key < root.value)
        root.left = insert(root.left, key);
    else
        root.right = insert(root.right, key);

    return root;
}
```
3. Удаление (Delete)

Сложнее, 3 случая:

| Случай    | Что делать                    |
| --------- | ----------------------------- |
| Нет детей | просто удалить                |
| 1 ребёнок | заменить узел                 |
| 2 ребёнка | заменить на inorder successor |

4. Обходы (Traversal)

| Тип       | Порядок                               |
| --------- | ------------------------------------- |
| Inorder   | left → root → right (даёт сортировку) |
| Preorder  | root → left → right                   |
| Postorder | left → right → root                   |

Сложность BST

| Операция | Среднее  | Худшее |
| -------- | -------- | ------ |
| Search   | O(log n) | O(n)   |
| Insert   | O(log n) | O(n)   |
| Delete   | O(log n) | O(n)   |

### В чем отличие сбалансированного дерева от несбалансированного? Приведите примеры.
**Несбалансированное дерево**

может превратиться в список:

```text id="05i2nn"
1
 \
  2
   \
    3
     \
      4
```

Проблема:

* операции → O(n)

**Сбалансированное дерево**

высота ≈ log(n)

```text
      4
     / \
    2   6
   / \ / \
  1  3 5  7
```

Преимущество:

* операции → O(log n)

Сравнение

| Критерий | Несбалансированное | Сбалансированное |
| -------- | ------------------ | ---------------- |
| Высота   | до n               | ≈ log n          |
| Поиск    | O(n)               | O(log n)         |
| Вставка  | O(n)               | O(log n)         |
| Удаление | O(n)               | O(log n)         |

 Примеры сбалансированных деревьев

**AVL Tree**

* разница высот ≤ 1
* частые повороты

**Red-Black Tree**

используется в Java:

```java
TreeMap
TreeSet
```

* менее строгий баланс
* быстрее на практике

Итог

* Дерево — иерархическая структура данных
* BST даёт быстрый поиск за счёт упорядоченности
* Без баланса → деградация до O(n)
* С балансом → стабильное O(log n)
